研究方法

1. 从入口追控制流

从 cli_main 开始，依次追到 ThreadManager、Session::spawn、submission_loop、run_turn、模型流处理和 Tool dispatch。

2. 用协议校正术语

通过 Op、EventMsg、AskForApproval、SandboxPolicy 的公开类型确认系统实际建模的边界。

3. 用 Handler 确认副作用

沿 Router、Registry、Orchestrator 到 Shell 与 Apply Patch，区分模型意图、策略决策和真实执行。

4. 用官方文档确认用户承诺

配置、AGENTS.md、CLI、沙箱与产品使用以研究日的官方文档为准。源码事实与文档承诺分别标记。

5. 不跨越公开边界

没有从客户端字段推断模型训练方式、隐藏 prompt、云调度拓扑或服务端基础设施。

如何刷新这份研究

新版本发布后，按以下顺序复核：

  1. 记录新的 tag、commit 与日期；
  2. 对比 protocol.rs 的 Op/Event 和权限类型；
  3. 对比 run_turn、ToolRouter、Orchestrator；
  4. 检查配置参考与 AGENTS.md 文档；
  5. 重跑本网站构建与全部内部链接检查；
  6. 只在证据变化时更新架构结论。
